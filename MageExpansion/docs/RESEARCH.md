# Mage Skills Expansion — этап 1: разведка (01.11.2026)

ТЗ: `Downloads\Divinity_II_Mage_Skills_Expansion_Prompt.md` (12 новых навыков мага). Всё ниже проверено на
установленной игре (`Divinity2.exe v1.4.700.56` + Div2Patch 0.97 + Reborn 1.5) статическим разбором
(`tools/re/x86re.py`) и чтением данных. **В игре ещё ничего не проверялось.** Воспроизвести выгрузку данных:

```
py -3 -I MageExpansion\tools\skills_dump.py "C:\Program Files (x86)\Steam\steamapps\common\divinity2_dev_cut" <папка>
```

## 0. Итог в пяти пунктах
1. Навыки — данные (`rpgstats_skillprototypes.xml`: ранги, мана, перезарядка, параметры), а **поведение навыка —
   жёсткий класс в exe**, выбранный по строке. Число классов фиксировано (82 имени, номера 1…0x54).
2. Движок уже умеет «новый навык на чужом коде»: атрибут `CodePath` (так сделаны 14 навыков NPC,
   например `Shaman_Fireball` → `CodePath="Fireball"`).
3. Но **имя навыка (UUID) тоже должно быть в жёсткой таблице exe**: дерево навыков, стартовый набор и панель
   быстрого доступа работают с номером навыка, а номер берётся только из таблицы `0x89D560`. Новое имя данными
   не добавить → нужен хук Div2Fix.
4. Из 12 навыков ТЗ готового класса-аналога нет почти ни у одного: замедление, заморозка, цепь, отбрасывание,
   луч с тиками, телепорт с проверкой коллизий, пассивки на события (убийство, «не получал урон»), сокращение
   перезарядки — всё это новый код в DLL поверх неисследованной боевой системы.
5. Реалистичный путь: сначала доказать **конвейер нового навыка** (дерево → изучение → панель → применение →
   сохранение → загрузка без мода) на Ice Bolt, затем добавлять механики по одной, каждую с проверкой в игре.

### 2.1 Структура навыка
```
<Skill UUID="Magic Missile" Name="Magic Missile" [CodePath="..."]>
  <Level Level="1" Description="... [1] ... [2] ..." LyricalDescription="..." EnduranceCost="6" CooldownTime="1" RequiredLevel="1">
    <Parameters Param1="1" Param2="6"/>     ← смысл ParamN свой у каждого класса; [N] в описании = ParamN
```
- `EnduranceCost` — мана, `CooldownTime` — секунды, `RequiredLevel` — уровень героя для ранга.
- У навыков игрока 15 рангов с описанием (у части — 16-й), всего записей `Level` до 30; ранги без описания
  (16–30) — вероятно, для NPC (TODO: не проверено).
- `ExtraStringParameter` (40 штук) — шаблон призываемого существа у навыков призыва.

## 4. Дерево навыков
`rpgstats_skilltree.xml` (Ep1 = Ep2, кроме строк 10–11 дракона). Строки 0–3 — магия (призыв/тьма, интеллект),
4–5 — воин, 6–7 — следопыт, 8–9 — общие, 10–11 — дракон (группировка по рядам — по составу; соответствие вкладкам
интерфейса — TODO в игре). Свободные клетки (без дракона): **(5,2)** в магическом блоке, (4,7) (5,7), (4,8) (5,8),
(5,9). То есть в существующую сетку помещается максимум 6 навыков, из них 1 — среди магических. Для 12 нужно
менять `skillTree.gfx` (Scaleform/AS2, через overlay) — не исследовано.

## 5. Сохранения
`.dxg` = заголовок + один zlib-поток (~9 МБ, секции `SaveLoadPreMisc - <класс>`). Строковые имена навыков в нём
только у учителей (`CRpgStats_V2_SkillTrainerManager`) и у Lua; панель — номера. Где лежат ранги навыков героя —
не найдено (TODO; по `0xB31490` — вероятно, по номеру).
**Следствие:** изученный новый навык игра сама запишет в сохранение (номер + ранг). Правило проекта «ничего не
писать в сохранения» здесь нарушается не нашим кодом, а самой игрой; удаление мода при изученном навыке — риск
(загрузка сохранения с неизвестным номером). Это надо решить до этапа 2 (см. §8, вопрос 2).

## 6. Визуальные эффекты и анимации
- Подходят без новых ресурсов: `MagicMissile_Cast/Travel/Impact`, `MagicBlast_*`, `LightBeam_A..D`,
  `Teleport_In/Away`, `DragonShield_*`, `BTI_Lightning`, `D_LTower_Beam`, `Curse_*`, `Blind_*`, `hit_spark`.
- **Ледяных эффектов в игре нет** (поиск по 301 имени: ice/frost/cold/freez — 0). Для Ice Bolt/Frost Nova нужен
  перекрашенный вариант (KFM/NIF из Effects.dv2 + текстуры) — пайплайн `d2tex`/`Reborn_FX` умеет только текстуры.
- Анимации заклинаний — `Human_{M,F}_Skills*.kf` (Characters.dv2); выбор анимации — в коде класса.

## 8. Ограничения и решения, которые нужны от пользователя
0. **(01.11, после проверки в игре) Только данными навык герою не выдать.** Навыки героя приходят из сохранения
   (старая игра) или из `init_savegame.dsg` (новая игра), а `DefaultSkills.xml` в обычной новой игре не применяется.
   Окно дерева показывает только навыки героя. Варианты: (а) Div2Fix выдаёт герою недостающий навык тем же вызовом,
   что и загрузка/DefaultSkills (`0x7692D0(id, 0, 5)`), перед построением окна дерева `0xA0D3A0` — работает и для
   старых сохранений; (б) правка `init_savegame.dsg` в overlay — только новые игры, двоичный формат не разобран.
   Рекомендация — (а). Следствие: навык ранга 0 попадает в сохранение при следующей записи (как все навыки героя).
1. **Новое имя навыка требует хука `0x89D560`** (и, вероятно, обратного «номер → имя» для иконки/подсказки).
   Номер: либо свободные существующие (`Chain Hit` 0x0E, `Newt` 0x39, дыры 0x1C/0x36 — всего 4), либо новые
   > 0x54 после разбора всех массивов/switch по номеру. На 12 навыков четырёх свободных номеров не хватает.
2. **Сохранения**: изученный навык попадёт в сохранение. Варианты: (а) принять (с проверкой загрузки без мода),
   (б) хранить ранги новых навыков в отдельном файле Div2Fix рядом с сохранением и не отдавать их игре — сложнее,
   но не трогает сохранения.
3. **Конфликт с модулем баланса** (`FOV_Patch_2.dv2`): overlay побеждает, значит наш
   `rpgstats_skillprototypes.xml`/`Skills_Localisation.xml` заменят его целиком. Сборщик обязан брать за основу
   действующую копию (так и делает `skills_dump.py`) и пересобираться при смене баланса.
4. Дерево: в магическом блоке 1 свободная клетка. Для 12 навыков — правка `skillTree.gfx` или навыки в чужих рядах.
5. Боевая система (урон, статусы, скорость, снаряды, рейкасты) не исследована — каждая механика из §7 = отдельная
   разведка функций exe + проверка в игре.

  проверка в игре**.
- Свободное имя-номер: `Newt` 0x39 — ни в одном прототипе, дереве, учителях и стартовых навыках не встречается.
  Использует ли exe номер 0x39 особо — **TODO** (проверка в игре). Дыры 0x1C/0x36 имени не имеют — по имени их не взять.
- Дерево: магический блок (ряды Y 2–3) занят полностью (последнюю клетку (5,2) занял Ice Bolt). Свободные клетки:
  (4,7), (5,7) — блок следопыта; (4,8), (5,8), (5,9) — общий блок (Mindread, Wisdom, LockPick…); (3–5,10), (4–5,11) —
  драконий. Клетка в магическом блоке — только правкой `skillTree.gfx` (не разобрано).
- **Итог опыта 3a (01.11):** `Dragon Burst` в облике человека непригоден. (1) Загрузчик прототипа `0x8A0B00` ставит
  признаки по номеру поведения; `[proto+0x5A]` (драконий/дирижабль: 0x31–0x39, 0x51–0x54) запрещает панель человека
  и ранги > 1 — Div2Fix снимает его у наших навыков после `0x8A4380`. (2) Применение: `switch` `0xA70AC4` по номеру
  поведения; ветка берёт компонент действия персонажа своего типа (`[char+0xC4]` → `0x74FF40` → `0x6A0300`).
  Dragon Burst ищет тип `0x14F684C`, у человека его нет → выход `0xA7172D`. Fireball — тип `0x14F683C`, есть у человека.
- Дерево расширяется вниз: строки X ≥ 6 (Div2Fix `TreeSheet=0`, проверено 01.11).
- **Свой навык, этап 1 — как герой применяет навык (01.11, трассировка `CastTrace=1`):**
  панель → `0x8FE33E`: `0x763AD0(id)` «можно ли» (мана `[stats+0x190]` против `EnduranceCost`×стат 0x2F, облик дракона,
  `out_of_mana`) → контроллер `[vtbl+0x70](id)` → `0x923FC0(id)` (ret 4): снова `0x763AD0`, прототип `0x74D350`, затем
  `switch` по номеру поведения `0x924440` (таблицы `0x9259B8`/`0x925A2C`). Ветка берёт компонент действия персонажа
  своего типа (`[stats+0xC4]` → `0x74FF40` → `0x6A0300`), пишет в него номер навыка `+0x20` (`0x955BB0`) и ранг `+0x24`
  (`0x955BC0`) и запускает `0x74FD30(компонент, 0)` (`0x92482C`). Поведения 0x0E, 0x1F–0x39 (драконьи, `Newt`) →
  `0x92599B` «ничего не делать». Ману списывает сам исполнитель заклинания: `0x764330(id)` (ret 4; вызовы из
  `0x969D2A` Fireball, `0x969537` Magic Missile). `0xA709D0`/`0x91E930` — путь NPC (Lua/ИИ), не героя.
  План: свой навык = поведение без ветки (`Newt` 0x39); Div2Fix перехватывает выход `0x92599B` для наших номеров и
  запускает свой обработчик; дальше нужны: перезарядка (`m_CooldownTimeLeft`, глобал `0x14F27E8`), анимация, поиск
  врагов, урон — не разобраны.
- **Свой навык, этап 5 — вид и анимация (разведка 01.11):**
  - Анимация броска — именованная последовательность в наборе анимаций персонажа (KFM): `Skill_Cast_Target`,
    `Skill_Cast_Self`, `Skill_Summon` (строки `0x13326A4…`). Объект броска (`0x95E0A0`) берёт компонент анимации
    `0x14F2FAC` (`[stats+0xC4]` → `0x74FF40`) и задаёт имя `0x739AF0(&std::string)` + `0x739B00(0)`; Lua
    `PlayAnimation` (`0x9BB5E0`): компонент `0x14F6450`, `0x74FD70`, `0x91F130(имя)`. Своя анимация = своя KF-последовательность
    для скелета героя (мужского и женского) + запись в KFM — не исследовано (формат, имена костей).
  - Эффект на персонаже: компонент `0x14F2FAC` → `0x741140(имя эффекта, …)` (вспышка броска `0x95E842`).
    Эффект в точке мира: менеджер `[0x14F170C]` → `0x810BA0(&имя, 1, &out)` → экземпляр; `0x810060`, `0x8103B0`,
    `0x8100E0(7, …)` — положение/масштаб (`0x95E4C1…0x95E545`, аргументы не разобраны). Эффект = прототип из
    `rpgstats_effectprototypes.xml` + `.item` (NIF 20.3.0.9) — свой файл можно собрать с нуля (свой писатель NIF).
  - **5а сделано (02.11):** `tools/nif_write.py` (378/381 эффектов игры байт в байт), `tools/fx_frostnova.py`; правило
    заголовка `CStreamableAssetData`: длина = размер − 17; текстуры для `icon_art.mip_chain` — uint8. Показ эффекта на
    герое через компонент `0x14F2FAC` без анимации не работает (проверено: не видна даже игровая вспышка).
  - **5б, разведка анимаций (02.11):** герой играет последовательности из `Characters.dv2`:
    `Win32\Characters\Human{Female,Male}\Player_{F,M}_Base[_1H|_1HSh|_2HSw|_Bow|_DW|_UA].kf` — по 57 последовательностей
    в каждом (в т. ч. `Skill_Cast_Target` 1,6 с, `Skill_Cast_Self` 1,5 с, `Skill_Summon`), 67 костей (`Hips`, `Spine…`,
    `LeftArm`, `LeftForeArm`, `LeftHand` + пальцы, `…TWIST`, ноги, `Reference`/`Reference NonAccum`), ключи —
    `NiBSplineCompTransformInterpolator` или `NiTransformInterpolator`+`NiTransformData`. Набор описывает KFM
    (`KFMs.dv2`, «Gamebryo KFM File Version 2.2.0.0b»): `Skeleton.nif`, корень, затем записи «номер последовательности,
    файл .kf, номер в файле, переходы ко всем остальным». У каждого вида оружия свой KF/KFM (7 × 2 пола = 14).
    Своя анимация: свой `.kf` (позы костей от покоя `Skeleton.nif` + свои повороты) и запись о нём в 14 KFM игрока.
